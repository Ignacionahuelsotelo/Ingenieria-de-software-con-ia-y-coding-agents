# H-001 — Ver el estado del grupo (personas y gastos)

**Base:** `docs/prd.md` §H-001 · `docs/architecture.md` §4
**Depende de:** nada. Es la primera historia.
**Dueño del código:** @dev

---

## 1. Contrato

### `GET /api/group`

Request: sin body, sin query params.

Response `200`:

```json
{
  "group": { "id": "g1", "name": "Viaje a Bariloche" },
  "people": [
    { "id": "ana", "name": "Ana" },
    { "id": "beto", "name": "Beto" },
    { "id": "caro", "name": "Caro" }
  ]
}
```

- `people` respeta el orden de inserción del `Map` del store.
- Si no hubiera personas, `people` es `[]`. Nunca `null`, nunca 404.

### `GET /api/expenses`

Request: sin body, sin query params.

Response `200`:

```json
{
  "expenses": [
    { "id": "e1", "description": "Cabaña", "amountCents": 120000, "paidBy": "ana", "splitBetween": ["ana", "beto", "caro"] },
    { "id": "e2", "description": "Nafta", "amountCents": 45000, "paidBy": "beto", "splitBetween": ["ana", "beto", "caro"] },
    { "id": "e3", "description": "Asado", "amountCents": 33000, "paidBy": "caro", "splitBetween": ["ana", "caro"] }
  ]
}
```

- Sin gastos: `{ "expenses": [] }` con `200`. **No** es un error.
- `amountCents` es siempre un entero. Ninguna respuesta de esta historia
  contiene un número con decimales.

### Errores

Esta historia **no tiene errores de cliente**. Ambas rutas son lecturas sin
parámetros y siempre devuelven `200`.

| Situación | HTTP | Body |
|---|---|---|
| Método no soportado en la ruta (`POST /api/group`) | 404 | (default de Express, no se personaliza en esta historia) |

## 3. Implementación

**Paso 1.** `backend/src/routes/group.js`:

```js
import { Router } from "express";
import { store } from "../store.js";

export const groupRouter = Router();

groupRouter.get("/", (req, res) => {
  res.json({ group: store.group, people: store.listPeople() });
});
```

**Paso 2.** `backend/src/routes/expenses.js` — solo el `GET` en esta historia.
El `POST` es H-003 y el `DELETE` es H-004; no adelantarlos.

```js
import { Router } from "express";
import { store } from "../store.js";

export const expensesRouter = Router();

expensesRouter.get("/", (req, res) => {
  res.json({ expenses: store.listExpenses() });
});
```

**Paso 3.** `backend/src/app.js` — agregar los dos `app.use` **sin tocar** las
líneas existentes de `health` ni `ask`:

```js
app.use("/api/group", groupRouter);
app.use("/api/expenses", expensesRouter);
```

**Paso 4.** `backend/tests/group.test.js` con los casos de §5, usando
`supertest` y `app` importada de `../src/app.js`, igual que `health.test.js`.

## 4. Riesgos

| Riesgo | Plan B |
|---|---|
| `store.listPeople()` / `listExpenses()` devuelven referencias al objeto guardado; un consumidor podría mutarlas. | No se copia defensivamente: nadie muta fuera del store (D-4). Si @qa demuestra una mutación, entra como historia nueva. |
| Montar el router en `/api/group` en singular puede confundirse con `/api/groups`. | La ruta es **singular** y sin id, es la decisión D-1. No se agrega alias. |
| Que el dev agregue de paso el `POST /api/expenses`. | Está prohibido: la tabla de §2 es cerrada y el `POST` es H-003. |

## 5. Tests (`backend/tests/group.test.js`)

- `GET /api/group` responde 200.
- `GET /api/group` devuelve `group.id === "g1"` y `group.name === "Viaje a Bariloche"`.
- `GET /api/group` devuelve 3 personas.
- Cada persona tiene exactamente las claves `id` y `name`, ambas strings no vacías.
- `GET /api/expenses` responde 200.
- `GET /api/expenses` devuelve 3 gastos.
- El gasto `e1` es `{ id: "e1", description: "Cabaña", amountCents: 120000, paidBy: "ana", splitBetween: ["ana","beto","caro"] }`.
- Todo `amountCents` de la respuesta cumple `Number.isInteger`.
- `expenses` es un array (no un objeto ni `null`).
