# H-006 — Pantalla única para usar todo esto

**Base:** `docs/prd.md` §H-006 · `docs/architecture.md` D-3, D-11, D-12
**Depende de:** H-001, H-002, H-003, H-004, H-005 (necesita los 6 endpoints).
**Dueño del código:** @dev

---

## 1. Contrato

Esta historia consume la API, no la extiende. El único contrato HTTP nuevo es
el servido de estáticos.

### `GET /`

Response `200`, `Content-Type: text/html`, con el contenido de
`frontend/index.html`.

También quedan servidos `GET /app.js` y `GET /styles.css` con `200`.

**Las rutas `/api/*` no cambian.** El estático se monta de forma que no las
pise.

### Llamadas que hace el frontend (todas relativas, mismo origen)

| Acción del usuario | Llamada |
|---|---|
| abrir la página | `GET /api/group`, `GET /api/expenses`, `GET /api/balances` |
| agregar persona | `POST /api/people` con `{"name":"Dani"}` y después `loadAll()` |
| cargar gasto | `POST /api/expenses` con `{"description","amountCents","paidBy","splitBetween"}` y después `loadAll()` |
| borrar gasto | `DELETE /api/expenses/:id` y después `loadAll()` |
| sacar persona | `DELETE /api/people/:id` y después `loadAll()` |

El frontend **nunca** llama a `POST /api/ask`. El asistente queda fuera de esta
pantalla (PRD §6), y así no hay forma de que la UI dispare una escritura por
chat (caso borde 10).

### Errores

Ante cualquier respuesta con status ≥ 400, el frontend lee `body.error` y lo
muestra **como texto, al lado del formulario que originó la acción**, en el
`<p class="error">` correspondiente. No usa `alert()`, no escribe en la consola
como único canal, y no recarga la página.

| Origen | Dónde se muestra el mensaje |
|---|---|
| `POST /api/people` | `#person-error` |
| `POST /api/expenses` | `#expense-error` |
| `DELETE /api/people/:id` (ej. 409) | `#person-error` |
| `DELETE /api/expenses/:id` | `#expense-error` |
| falla de red / fetch rechazado | `#global-error`, texto `"No se pudo conectar con el servidor"` |

Un error deja el grupo intacto: el `loadAll()` posterior a un fallo **no se
ejecuta** (no hay nada que refrescar) y el formulario conserva lo que el usuario
escribió.

## 3. Implementación

### Paso 1 — servir el estático desde `backend/src/app.js`

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const frontendDir = path.join(path.dirname(fileURLToPath(import.meta.url)), "../../frontend");
app.use(express.static(frontendDir));
```

Va **después** de `express.json()`. Las rutas `/api/*` conviven sin conflicto
porque no existen archivos con esos nombres en `frontend/`.

### Paso 2 — `frontend/index.html`

Una sola página. Ids obligatorios (los usa `app.js` y los verifica el test):

| Id | Elemento | Para qué |
|---|---|---|
| `#group-name` | `<h1>` | nombre del grupo |
| `#people-list` | `<ul>` | personas, cada una con su botón de sacar |
| `#expenses-list` | `<ul>` | gastos, cada uno con su botón de borrar |
| `#balances-list` | `<ul>` | balances |
| `#transfers-list` | `<ul>` | transferencias |
| `#settled-msg` | `<p>` | texto "Están a mano" cuando `settled === true` |
| `#person-form` | `<form>` | alta de persona |
| `#person-name` | `<input type="text">` | nombre |
| `#person-error` | `<p class="error">` | error de personas |
| `#expense-form` | `<form>` | alta de gasto |
| `#expense-description` | `<input type="text">` | descripción |
| `#expense-amount` | `<input type="text" inputmode="decimal">` | monto **en pesos** |
| `#expense-paidby` | `<select>` | pagador, una `<option>` por persona |
| `#expense-split` | `<div>` | un `<input type="checkbox">` por persona, `value` = id |
| `#expense-error` | `<p class="error">` | error de gastos |
| `#global-error` | `<p class="error">` | error de conexión |

`<head>` obligatorio: `<meta charset="utf-8">` y
`<meta name="viewport" content="width=device-width, initial-scale=1">`.
Carga: `<link rel="stylesheet" href="/styles.css">` y
`<script src="/app.js" defer></script>`. Sin `type="module"` no hace falta;
usar `defer` es suficiente.

El monto se pide **en pesos**, y el `<label>` lo dice: `Monto (en pesos)`.
El placeholder es `485,00`.

### Paso 3 — `frontend/app.js`

**Las dos únicas funciones de conversión de toda la app** (D-3). Nada más
convierte:

```js
/** 48500 -> "$485,00" · -10000 -> "-$100,00". Sin separador de miles. */
function formatCents(cents) {
  const sign = cents < 0 ? "-" : "";
  const abs = Math.abs(cents);
  return `${sign}$${Math.floor(abs / 100)},${String(abs % 100).padStart(2, "0")}`;
}

/** "485,00" o "485.5" o "485" -> entero de centavos. null si es inválido. */
function pesosToCents(raw) {
  const s = String(raw ?? "").trim().replace(",", ".");
  if (!/^\d+(\.\d{1,2})?$/.test(s)) return null;
  const [entera, dec = ""] = s.split(".");
  return Number(entera) * 100 + Number(dec.padEnd(2, "0"));
}
```

`pesosToCents` hace aritmética entera a propósito: nunca
`parseFloat(x) * 100`, que redondea mal (`19.99 * 100 === 1998.9999…`).

**Carga y render (D-12: se repinta todo, siempre):**

```js
async function loadAll() {
  const [group, expenses, balances] = await Promise.all([
    fetch("/api/group").then((r) => r.json()),
    fetch("/api/expenses").then((r) => r.json()),
    fetch("/api/balances").then((r) => r.json()),
  ]);
  renderGroup(group);
  renderExpenses(expenses.expenses, group.people);
  renderBalances(balances);
}
```

**Envío de un gasto** — forma exacta de la llamada:

```js
async function submitExpense(e) {
  e.preventDefault();
  clearErrors();

  const amountCents = pesosToCents(document.querySelector("#expense-amount").value);
  if (amountCents === null || amountCents <= 0) {
    return showError("#expense-error", "Poné un monto en pesos mayor a cero, por ejemplo 485,00");
  }
  const splitBetween = [...document.querySelectorAll("#expense-split input:checked")].map((c) => c.value);
  if (splitBetween.length === 0) {
    return showError("#expense-error", "Elegí al menos una persona entre quienes se divide");
  }

  const res = await fetch("/api/expenses", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      description: document.querySelector("#expense-description").value,
      amountCents,
      paidBy: document.querySelector("#expense-paidby").value,
      splitBetween,
    }),
  });

  if (!res.ok) return showError("#expense-error", (await res.json()).error);

  document.querySelector("#expense-form").reset();
  await loadAll();
}
```

La validación del cliente **no reemplaza** a la del server: es solo para dar un
mensaje rápido. El server valida igual y su `error` se muestra tal cual.

**Reglas de render:**

- Todo texto que venga del server se inserta con `textContent`, **nunca** con
  `innerHTML`. Un nombre con `<script>` no puede ejecutarse.
- Cada balance se muestra como: `Ana · le deben $485,00` si es positivo,
  `Beto · debe $100,00` si es negativo, `Caro · está en cero` si es 0.
  (Para los negativos se muestra el valor absoluto, porque la palabra "debe" ya
  lleva el signo).
- Cada transferencia: `Caro le paga $385,00 a Ana`.
- Si `settled === true`: `#transfers-list` queda vacío y `#settled-msg` muestra
  `Están a mano: nadie le debe nada a nadie`. Si es `false`, `#settled-msg`
  queda vacío.
- Cada persona y cada gasto se renderiza con un botón `Sacar` / `Borrar` que
  dispara el `DELETE` correspondiente y después `loadAll()`.
- El `<select>` de pagador y los checkboxes de reparto se **reconstruyen** en
  cada `loadAll()` a partir de `group.people`.
- El pagador **no** se autoselecciona ni se fuerza dentro del reparto (caso
  borde 2). Los checkboxes arrancan todos marcados por comodidad, pero el
  usuario puede desmarcarlos todos, incluido el del pagador.
- Al abrir la página: `document.addEventListener("DOMContentLoaded", loadAll)`.
- Todo `fetch` va dentro de un `try/catch`; en el `catch` se muestra
  `"No se pudo conectar con el servidor"` en `#global-error`.

### Paso 4 — `frontend/styles.css`

Mobile-first, sin dependencias:

- `body { max-width: 640px; margin: 0 auto; padding: 1rem; font-family: system-ui, sans-serif; }`
- Inputs y botones con `font-size: 16px` como mínimo (abajo de eso iOS hace zoom
  al enfocar) y alto táctil de al menos `44px`.
- Inputs de ancho `100%` y `box-sizing: border-box`.
- `.error { color: #b00020; }` y vacío por defecto (sin `display:none`, así no
  salta el layout).
- Nada de media queries para escritorio: el ancho máximo alcanza.

### Paso 5 — `backend/tests/static.test.js`

Verifica el servido de estáticos, no el DOM. No se agrega jsdom ni testing
library (D-13).

## 4. Riesgos

| Riesgo | Plan B |
|---|---|
| `express.static` montado antes de `express.json()` o pisando `/api`. | Montarlo después de `express.json()`. Si un test de `/api/*` se pone rojo, mover el `app.use(express.static(...))` al final del archivo. |
| La ruta relativa `../../frontend` se rompe según desde dónde se ejecute `node`. | Se resuelve con `fileURLToPath(import.meta.url)`, que no depende del `cwd`. No usar `process.cwd()`. |
| Redondeo de pesos a centavos con floats. | `pesosToCents` es aritmética entera. Hay test de `19,99 → 1999`. |
| XSS por nombre o descripción con HTML. | `textContent` siempre. Está prohibido `innerHTML` en `app.js`. |
| Doble submit crea dos gastos. | Aceptado: el PRD dice que la app no adivina duplicados (caso borde 6) y el borrado existe. No se agrega deshabilitado de botón como requisito. |
| Testear el DOM requeriría jsdom. | No se testea el DOM en esta historia. La verificación de la UI es manual, con el checklist de §6. |
| Tentación de meter el asistente en la pantalla. | Fuera de alcance (PRD §6). No se agrega. |
