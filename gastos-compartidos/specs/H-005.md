## 1. Contrato

### `GET /api/balances`

Request: sin body, sin query params.

Response `200` con el grupo semilla intacto (valores exactos, verificables):

```json
{
  "balances": [
    { "personId": "ana", "name": "Ana", "balanceCents": 48500 },
    { "personId": "beto", "name": "Beto", "balanceCents": -10000 },
    { "personId": "caro", "name": "Caro", "balanceCents": -38500 }
  ],
  "transfers": [
    { "fromPersonId": "caro", "from": "Caro", "toPersonId": "ana", "to": "Ana", "amountCents": 38500 },
    { "fromPersonId": "beto", "from": "Beto", "toPersonId": "ana", "to": "Ana", "amountCents": 10000 }
  ],
  "settled": false
}
```

Cuando nadie debe nada:

```json
{ "balances": [ { "personId": "ana", "name": "Ana", "balanceCents": 0 } ], "transfers": [], "settled": true }
```

Reglas del contrato:

- `balances` incluye a **todas** las personas del grupo, también las que están
  en `0`. Su orden es el de `store.listPeople()`.
- `balanceCents` **positivo = le deben**; **negativo = debe**. Es el signo el
  que distingue; no se agrega ningún campo `owes`/`isOwed`.
- La suma de `balanceCents` es **siempre exactamente 0**.
- `transfers` es la salida literal de `simplifyDebts`, sin reordenar ni
  reformatear. Nadie aparece a la vez como `from` y como `to` (lo garantiza el
  algoritmo: un balance es positivo o negativo, no ambos).
- `settled` es `true` **si y solo si** `transfers.length === 0`. Es el "están a
  mano" del PRD, expresado como dato y no como error.
- Grupo sin personas: `{ "balances": [], "transfers": [], "settled": true }` con
  `200`.
- Todos los montos son enteros de centavos. Ninguno tiene decimales.

### Errores

Esta historia **no tiene errores de cliente**. La ruta es una lectura sin
parámetros y siempre devuelve `200`.

## 3. Implementación

**Paso 1 — `backend/src/routes/balances.js`.** El cálculo se **reutiliza tal
cual**; acá no se escribe ni una línea de matemática:

```js
import { Router } from "express";
import { store } from "../store.js";
import { computeBalances, simplifyDebts } from "../domain/balances.js";

export const balancesRouter = Router();

balancesRouter.get("/", (req, res) => {
  const balances = computeBalances(store.listPeople(), store.listExpenses());
  const transfers = simplifyDebts(balances);
  res.json({ balances, transfers, settled: transfers.length === 0 });
});
```

**Paso 2 — `backend/src/app.js`:** `app.use("/api/balances", balancesRouter);`

**Paso 3 — tests.** `beforeEach(() => store._reset())`. Los números esperados
del grupo semilla, ya calculados a mano, para usar como asserts duros:

| Persona | Cuenta | `balanceCents` |
|---|---|---|
| Ana | `+120000 −40000 −15000 −16500` | `48500` |
| Beto | `+45000 −40000 −15000` | `-10000` |
| Caro | `+33000 −40000 −15000 −16500` | `-38500` |

## 4. Riesgos

| Riesgo | Plan B |
|---|---|
| Tentación de reordenar o "embellecer" `transfers` (ordenar por nombre, agrupar). | Prohibido: el orden es el que produce `simplifyDebts` y los tests lo fijan. |
| Tentación de omitir del listado a quien está en 0. | Prohibido: el PRD exige incluirlos (H-005, criterio 1). |
| Tratar el grupo saldado como un 404 o un error. | Prohibido: es `200` con `settled: true` (caso borde 7). |
| Devolver montos en pesos "para que el front no convierta". | Prohibido (D-2). |
| Duplicar el cálculo en la ruta en vez de importar el dominio. | La ruta importa `computeBalances`/`simplifyDebts`. Cero matemática nueva. |

## 5. Tests (`backend/tests/balances-api.test.js`)

- `GET /api/balances` responde 200.
- Con la semilla, `balances` tiene 3 entradas.
- Con la semilla, Ana tiene `balanceCents === 48500`.
- Con la semilla, Beto tiene `balanceCents === -10000`.
- Con la semilla, Caro tiene `balanceCents === -38500`.
- La suma de todos los `balanceCents` es exactamente 0.
- Todos los `balanceCents` cumplen `Number.isInteger`.
- Cada balance tiene exactamente las claves `personId`, `name`, `balanceCents`.
- Con la semilla, `transfers` tiene 2 elementos y `settled === false`.
- La suma de los `amountCents` de `transfers` es igual a la suma de los balances positivos (48500).
- Ningún `personId` aparece a la vez como `fromPersonId` y como `toPersonId`.
- Aplicar todas las transferencias sobre los balances deja a todos en 0 (verificarlo con una reducción en el test).
- Una persona recién agregada aparece en `balances` con `balanceCents === 0`.
- Borrados todos los gastos, todos los balances son 0, `transfers` es `[]` y `settled === true`.
- Deuda circular: con un grupo donde A le debe a B, B a C y C a A por el mismo monto, `transfers` es `[]` y `settled === true`.
- Un gasto que no divide exacto (100 entre 3) mantiene la suma de balances en 0.
